# Playwright 验证延时收起弹层：整场景须单调用内完成

## 结论

验证带 HIDE_DELAY（300ms）延时收起的弹层链（side-menu / menu 弹层）时，`hover → 停留 → 断言` 全序列必须放在**同一次 playwright 调用**（run_code 脚本）内完成；重开已关的链前必须先把鼠标移出再移入；断言面板几何前先用 `elementFromPoint` 确认目标点确实命中锚点行。

## 原因

- 工具调用间的间隔（evaluate 往返、locator 超时重试等）远超 300ms，链在调用间隙被自身延时计时器正常关闭——这是设计行为，但会让分步验证误判为"弹层没开/回归失败"。
- 鼠标已停在目标元素上时，再次 `mouse.move` 到同坐标不产生 mouseenter（无边界穿越），依赖 hover 触发的浮出不会发生。
- 页面滚动会让弹层面板从静止的鼠标下方移出，触发面板 mouseleave → 整链 300ms 后自关；先滚动后开链，或滚动后用点击重开。
- 跨过面板内其他组行的移动路径会触发途经组行的 `showLayer`（同层换内容重定位），后续按旧行内容定位会落空。
- 移位测试夹具（如把实例平移到视口右缘）打开的旧链面板会盖住移位后的锚点行，hit-test 命中的是弹层面板而非锚点行，锚点 hover 永不触发；复测前须 ESC 清链并把鼠标移到远处等链收净。

## 注意

- 单调用内的每步 hover 后等待须略大于 HIDE_DELAY（建议 400-450ms）再断言，避免动画未完成或计时器尚未触发。
- 需要观察"延时收起"本身时（如断言 14 更深层依自身计时收起），在单调用内按 250/150/150ms 间隔采样弹层数即可分辨关闭次序。
- 与「Playwright 后台页面」坑独立：本条在页面前台可见时同样发生，根因是组件自身的延时收起语义。
