# inert 子树内元素不参与 hit-test：:hover 不匹配、点击无效

## 结论

带 `inert` 属性的元素，其整棵子树不参与指针 hit-test：

- 子树内元素**不匹配 CSS `:hover`**（依赖 `xx:hover 子级` 显现的元素不会出现）。
- 子树内元素的点击等鼠标事件**不会派发**。

把"hover 显现 / 可点击"的浮层元素（如 side-menu 收藏星标）移入 inert 行内部，会使其在禁用行上彻底失效；放在 inert 容器**外部**（如父级 `li` 下）则不受影响。

## 原因

inert 的语义是让整棵子树对用户不可交互：浏览器 hit-testing 直接"看穿"该子树，指针事件不命中其中任何元素。`:hover` 依赖 hit-test 结果，因此同样不匹配。

## 注意

- 反向利用：若希望禁用行上的附属操作一并失效，把操作元素移入 inert 容器内即可，无需额外判禁用逻辑。side-menu 星标移入 `mu-side-menu__item` 后即获得"禁用行不可收藏"语义。
- inert 只拦截指针交互，不拦截视觉：子树内容仍按普通 CSS 渲染（`[inert]` 弱化样式需显式写）。
