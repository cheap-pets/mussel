## 3. 修订 1 自身的问题

### 3.1 [致命] §4.2「clip 仍取原脏格矩形」「行/列脏带无需扩展」与 2.1-3 自相矛盾，overlay 残影并未解决

hover 高亮、编辑描边画在 overlay pass，其变化范围是**归一后区域的整个包围盒**；region pass 只保证内容正确，不覆盖 overlay 状态变化。反例：合并区域占 row 5–8，hover 从区域移到 row 3，壳侧 `bandRegionsOf` 产出带 `[3,6)`（table-ex.vue:625-628，取 prev/next hover 行区间），区域 row 6–8 的高亮像素在带外，清除不掉——即 2.1-3 要消灭的残影。

修复（二选一）：

1. painter 内归一后，`{cell}` / `{rows}` / `{cols}` 的 range **与 clip 一并扩展到相交 region 的包围盒**。重绘幂等，单次交互成本可接受。
2. 含 span 相交的失效拆为多条 region，触发既有「多区域合帧为整幅」路径（painter.js:1112-1120），零新机制。

方案 2 更符合「正确性优先」的现有注释语义，推荐优先评估。

### 3.2 [警告] 2.2-1 事实锚点错误

`demo/src/data/table-ex/main-view.vue` 无重复 field：`name`/`status`/`count`/`amount`/`date`/`memo`/`checked` 各出现一次，无 `level` 列。「本仓库 demo 已存在同 field 多列」不成立。

处置：「同 field 多列歧义」作为潜在用户场景的防御保留（key 优先 + 多列命中警告），但理由表述更正为「用户场景防御」，删除 demo 佐证，避免实施者去 demo 找不存在的参照。

### 3.3 [警告] §4.4 跨列主格「按单列宽参与行高，属已知低估」方向反了

宽度口径小于实际区域宽 → 折行数偏多 → 行高**高估**，非低估。

处置：构建期 spans 与 colWidths 均已知，跨列（colspan>1 且 rowspan=1）主格直接按**区域宽**参与行高，消除该已知偏差；不再保留「按单列宽」的降级口径。

### 3.4 [小问题] §4.5 cellX 不重算依赖隐式巧合

归一只覆盖 `rowIndex`/`colIndex`，`cellX` 仍是相对**原命中列**内容区的偏移。当前唯一消费者是树槽判定（isTreeArrowSlot），树列无合并、归一前后不变，碰巧安全——但这是巧合不是契约。

处置：设计文档显式写明「cellX 语义绑定原始命中列（覆盖格或主格列），归一不重算；新增 cellX 消费点前必须先重算或改锚」。

### 3.5 [小问题] 三段式拆循环波及无 spans 快路径，「零回归」须降级表述

背景与内容从「逐行交替」改为「先全背景后全内容」，是对 `paintCellRange` 的结构性改动，无 spans 表格同样经过。不透明背景下像素理论等价，但承诺应为「快路径仅多一次 null 判断与空 regions 遍历 + 绘制顺序重排（像素等价，以自检验证）」，并列入 P0 验收：既有 painter 自检全过 + 关键帧像素对照。

### 3.6 [小问题] 树父链切断缺少落地锚点

§3.1 规则 4「祖先链由 DFS 前序遍历的栈推导」要求 spans 构建期拿到父链，而 `flatInfo` 只有 `levels`/`hasChildren`（use-tree-rows.js）。§5 同步表与 §11 文件清单均未体现该改动。

处置：二选一并写入文件清单——扩展 `buildFlatRows` 输出 `parentChains`（或每行父 key），或 spans 构建期对 displayRows 重跑一次 DFS 推导（不依赖 flatInfo）。推荐前者（单一事实源）。

### 3.7 [小问题] tag/link 列 `autoRowSpan: true` 静默无效仍无警告

2.2-3 自己指出的问题，修订 1 只给了 string/Function 出路；`true` 形态在 tag/link/button 列（值为数组/对象，Object.is 恒不等）仍静默无效。

处置：构建期发现某列 `autoRowSpan: true` 且列类型属图形/条目列（值恒非原始值）时，dev 警告一次「该列 true 形态不会产生合并，请用 string/Function 键」。
