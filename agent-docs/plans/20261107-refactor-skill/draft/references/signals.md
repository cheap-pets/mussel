# 信号识别全集（S1–S8）与判定阈值

配套 SKILL.md 第 2 步（问题清单）。逐信号扫描下表，命中即记入问题清单并附 `文件:行号` 证据。"匿名示例"列是已验证案例的模式化描述，供对照理解，非判定依据。

## 信号识别表（信号 → 可执行识别方法 → 结论）

| # | 信号 | 识别方法（可执行） | 判定结论 | 匿名示例 |
|---|---|---|---|---|
| S1 | re-export 转口 | 逐聚合文件的 export 项核对：符号 import 源是另一实现文件，本文件无该符号的定义/包装逻辑（import 源与实现分离，纯转发） | import 图失真：消费方指向聚合壳，实现被二跳遮蔽 | 聚合文件尾部转发多个符号；入口文件整体转发一套实现；交互入口整体转发一组调度实现 |
| S2 | 运行时注入依赖 | 参数袋（把回调和状态打包传入的大对象）的键被 ≥2 文件回填或调用：grep `袋名.键名`，读/写两侧分处不同文件，且两文件间无 import 边 | import 图失真：真实调用边只在运行时出现 | 十余个功能模块经一个 40+ 键的参数袋互相调用，import 图完全不可见 |
| S3 | 隐式共享可变状态 | 单对象字段数大（>20 量级）且写入点分布多文件（grep `对象名.` 后筛赋值形态）；或依赖"使用前手动 sync"协议（grep 协议函数名） | 状态读写面不可从签名推断 | 某 30+ 字段状态对象被 6+ 模块共享引用，靠每次使用前手动调用同步函数 |
| S4 | 同源重复 | 双证据任一成立：① 注释自认"逐字同源 / copy of / 保持一致"；② ≥2 文件同函数体（去空白后逐 token 相等，可脚本比对）。仅"看起来像"**不判**同源 | 漂移风险：一处修复另一处漏 | 两个工具函数注释自认逐字同源；一段业务逻辑在多文件复制粘贴 |
| S5 | 跨层反向依赖 | 按分层模型查下层→上层 import 边；或单条 import 边拖入重载荷传递闭包（如整条 UI 组件链） | 层边界失真：影响面横跳，低层受高层牵制 | 低层 import 上层函数，连带把上层整套 UI 组件依赖拖进低层 |
| S6 | 命名无区分度 | 对 ≤3 字符的短标识符按全库 grep 命中数排序，取头部逐个判定是否跨模块同形异义（同名指不同对象） | 符号检索被噪音淹没 | 某两字母缩写在多个模块中分别指不同对象，全库同形异义 |
| S7 | 目录/文件多职责 | 单文件/目录承载互不相关多个域：文件头自述多职责、行数排序头部（`wc -l` 取头部作候选）、同文件导出互不消费的符号组 | 按名定位功能的路径断裂 | 某文件同时承担转口、事件调度、状态维护三个域 |
| S8 | 参数形态超标 | 函数位置参数 >5；或打包对象 >10 字段（阈值依据见下表） | 调用点需对照签名逐个释义，参数错位不可目检 | 某内部函数 8 个位置参数，每个调用点都需回看签名才能释义 |

## 判定阈值与依据

阈值是校准默认值，有实测证据可调，不是硬编码教条：

| 阈值 | 默认值 | 依据 |
|---|---|---|
| 位置参数转打包 | >5 | 5±2 为短期记忆组块上限：调用点超过 5 个字面量序列即无法目检语义，错位不可见 |
| 打包字段语义分组 | >10 | >10 字段单袋必混装多语义域；消费方只消费子集，子集边界即分组边界 |
| 共享原语独立成模块 | 被 ≥2 层消费 | 1 层消费留本层；2 层即产生跨层检索需求与反向边风险。结构判定，非数值阈值 |
| 同源重复判定 | 双证据任一（注释自认 / 归一化后同函数体） | 单一"相似"证据误判率高，会合并不该合并的代码；证据不足则不提取 |
| 痛点文件入围 | 行数排序头部 + import 入度/出度异常 + 文件头自述多职责 | 体量/耦合/职责三个独立维度的代理指标联合定位，单指标会误筛 |

## 停止条件（何时拆批 / 推迟 / 禁止启动）

1. **批次容量**：单批文件数/风险级超出执行槽位单会话负荷即拆批。按风险级隔离——机械归一类与"需专项设计 + 专项校验"类不混批。宁可多批不硬塞。
2. **基线前置**：探针基线不可回溯，无基线的 S/E/C 改动批次不得启动（见 references/verification.md）。
3. **在途改动冲突**：目标区存在未提交改动且无法行级避让（只动 import/命名行、禁触逻辑区）时，该区域推迟批次。

## "明确不做"划定程序

不做清单与优化清单同权重，逐条标注理由类型并记录在设计文档：

| 不做理由类型 | 判定 |
|---|---|
| 收益/成本倒挂 | 失真源已可用低成本手段补齐（如 S2 已用声明手段显式化），根治需架构换血，超出"检索效率"目标 |
| 收益为零或负 | 改名/搬移脱离生态惯例，反而降低检索性（如平台 API 语境词不改名） |
| 风险当批不可控 | 改动落在未提交区或需特殊校验，当批无法完成验证闭环 → 移入后续独立批次 |
