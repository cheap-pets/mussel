# 验证矩阵：改动分类、方法适用性与充分组合

配套 SKILL.md 第 3 步（标验证方式）与第 5/6 步（实施与验证）。核心逻辑：**改动类型决定验证组合**——不同 diff 形态的可证明性不同，验证不足会把行为回归漏到线上，验证过度会拖垮批次交付。

## 改动分类（按 diff 形态判别）

实施前先判别本批每项改动所属类型；一批含多类时整批按最高要求类型验证。

| 类型 | 定义 | diff 形态判别 | 验证难度 | 匿名示例 |
|---|---|---|---|---|
| M 机械归一 | 改名/直引/平移，语义逐行等价 | 仅 import 行改写、标识符替换、整块平移，无新逻辑 | 低（等价性可证） | 删转口直引、同名消歧改名 |
| S 结构拆分 | 新建模块，代码从源文件迁出 | 新文件 + 源文件删除块 + 两侧引用改写 | 高（等价性不可逐行证明） | 跨层共享纯函数拆独立模块、重复逻辑合并出的公共模块 |
| E 行为等价提取 | 重复实现合一为单一事实源 | ≥2 处删除相似块 + 1 处新增定义 + 调用点改引 | 高（"两处等价"是断言不是事实） | 同源函数与复制粘贴逻辑的提取 |
| C 签名收敛 | 参数打包/分组，调用点重排 | 函数签名与调用点参数列表同步变化 | 中-高（编译期可静默通过） | 位置参数转打包对象 |

## 方法适用性表

| 方法 | 验证什么 | 适用条件 | 失效场景（机理） | 成本 |
|---|---|---|---|---|
| build / 编译自检 | 语法与引用完整性 | 任何改动；永远第一步 | 类型系统不覆盖运行时动态键名（参数袋场景漏转换键名编译不报错）：曾出现漏转一个动态查找键，build 全过，运行时多处引用错误、对应功能全断 | 低 |
| 残留引用扫描 | 旧符号清零 | 改名/直引/搬移/提取后 | `git grep` 不覆盖未跟踪新文件（假阴性）；动态拼接的标识符 grep 不到。对策：全仓 grep 含 untracked、按自由标识符匹配 | 低 |
| diff 等价审计 | "仅机械归一"的证明 | M 类，diff 可逐行配对 | S/E/C 无法逐行配对；只看形状不核语义会漏配对行内的表达式改动。对策：配对须同时核对等价 | 中 |
| 探针基线比对 | 行为冻结等价 | 有可触发组件/模块行为的运行环境 | 覆盖面 = 探针点位覆盖面：未触达的交互路径比对不到（曾有缺陷只靠对应交互点位才暴露）；基线不可回溯，改码前采集落盘是硬顺序 | 高 |
| 像素/渲染快照断言 | 渲染输出等价 | 绘图、图表等视觉输出组件 | 对非视觉逻辑（纯函数/数据流）无感；计数断言粒度粗，与日志原文序列互补 | 中 |
| API 冻结核对 | 对外契约零变化 | 库/组件/模块对外导出的重构 | 不检内部行为；范围须含对外导出、事件、暴露方法、事件时序（用 git diff 复核） | 低 |

## 执行次序（低成本排除法）

build → 残留引用扫描 → diff 等价 / API 冻结 → 探针基线 + 像素/渲染快照断言。

前序通过**不替代**后序，只让后序聚焦（前序已排除的类别让高成本手段专注剩余风险面）。

## 充分组合（每类改动的"够用"判据）

| 改动类型 | 充分组合（够用） | 补充手段（按需） | 理由 |
|---|---|---|---|
| M 机械归一 | build + 残留扫描 + diff 等价审计 | 触及运行时动态查找（动态 import / 键名拼接）时，探针基线升级为充分项 | 逐行配对证明语义等价，行为正确性由等价性传递，diff 等价审计即基线/像素断言的高效替代；动态查找是等价性传递的断点 |
| S 结构拆分 | build + 残留扫描 + 探针基线（日志警告/错误原文序列 + 渲染快照断言计数，逐字比对，允许时间戳/行号类漂移） | 模块对外导出变化时加 API 冻结 | 迁出代码在新位置可能带回不同依赖闭包（切断重边正利用此机理）；diff 无法配对，行为面只能由基线证明 |
| E 行为等价提取 | build + 残留扫描 + 探针基线 + 等价性校验点核对 | — | "两处同源"是断言：须以注释自认的约束 / 既有调用约束为校验点逐条核对，基线再证消费侧行为不变 |
| C 签名收敛 | build + 全部调用点逐一参数位核对 + 探针基线 | 有类型系统时加类型检查 | 对象键无序，打包/分组错位编译期可静默通过，只能点位核对；基线兜底运行时 |

## 探针基线的适用边界与豁免程序

### 必须采基线

- S / E / C 类改动；
- M 类触及运行时动态查找（动态 import / 键名拼接）；
- 任何影响面不可静态推断的改动。

### 可豁免（以 diff 等价审计替代）

- 纯 M 类，且不触及动态查找、不动行为路径。

### 豁免程序合法性

豁免决定须在设计文档写明**理由与 diff 配对范围**，验证员核对配对完整性后方可免采。**无记录的豁免视为未验证。**

### 顺序约束（不可违反）

- 基线是**实施者职责**（写进任务简报），改码前采集落盘。
- 基线不可回溯：验证员无法事后补采，只能同口径复采后逐字比对。

### 基线内容口径

- 可触发行为的运行环境下，采集行为可观测输出序列（如日志警告/错误原文序列、渲染断言计数）。
- 比对口径：逐字比对，允许时间戳/行号类非语义漂移。
- 点位设计：覆盖本批改动触达的交互路径——未触达的路径比对不到，点位缺口 = 验证缺口。
