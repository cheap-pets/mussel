## 次序规则（先机制后搬移）

1. **机制类（删转口 / 声明 / 改名）先于搬移类（拆模块 / 提取 / 目录拆分）。**
   - 原因：机制类只动 import/注释/命名行，diff 可逐行配对，走 M 类（机械归一）低成本验证通道；搬移类动文件边界，必须先采探针基线（S/E 类验证）。
   - 混批规则：一批含多类改动时，整批按所含最高要求类型执行验证组合。
2. **依赖序：A 类（依赖图失真）先修，修完复测再进 B/C/D。**
   - 原因：依赖图失真状态下判定的目录拆分边界（S7 手段）不可信，会把多职责判定建立在歪曲的图上。
   - 复测程序：A 类修完后，用重构判据检验——只靠静态手段（import 图、文件头、签名、grep）能否回答"这功能在哪 / 改这里影响谁"；未达标再进 B/C/D。
3. **搬移只用于切断重依赖边（S5）或建立单一事实源（S4），不为美学搬移。**
   - 原因：每次搬移动文件边界，验证成本从"逐行配对"跳到"行为基线"，须有对等收益。
4. **参数收敛（S8）只在接触调用点时顺带执行**，不开专项批次（除非已引发实际缺陷）。
