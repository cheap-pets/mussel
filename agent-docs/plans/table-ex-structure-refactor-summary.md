## 1. 重构目的

**不是**让代码"更好看"，而是**提升 agent 对代码的功能检索与影响面分析效率**。判断标准：agent 能否只靠静态手段（import 图、文件头、函数签名、grep）回答"这功能在哪、改这里影响谁"。

## 2. 根因：import 图 ≠ 依赖图

本次全部问题都归结到一个根因——静态 import 关系不能代表真实依赖：

| 失真源 | 本次实例 |
|---|---|
| re-export 聚合层 | cell-painters 尾部转口 8 符号、editor.js 转口 editor-resolve 全套、interactions.js 转口 schedulers |
| 运行时依赖注入 | 10 个 composable 经 ~40 键 host 袋互相调用（hitAt/clearCellSelection/applyTreeToggle…），import 图完全不可见 |
| 隐式共享可变状态 | paintState（31 字段）被 6+ 模块共享引用，靠每次绘制前手动 sync |
| 跨层反向依赖 | paint 层 import 编辑层几何函数（连带拖入 form 组件链） |

四类失真源的可执行识别方法见 §5.1（对应 S1/S2/S3/S5）。

## 3. 重构思路（通用原则）

1. **数据先行**：先建调用层级结构底图（分层模型 + 目录依赖图 + 关键链路 + 数据对象字段表），以数据定位问题，不凭感觉。
2. **按"检索效率影响"排序**，不按代码美学：先修根因级（依赖图失真），再修目录语义、重复代码、参数风格。
3. **机制优先于搬移**：先改"依赖可见性"（消 re-export、声明消费面、命名消歧），再动代码位置；搬移只用于切断重依赖边。
4. **小批交付**：每批独立可提交、独立可验证；批次容量按执行槽位现实收敛（单会话负荷），宁可多批不硬塞。
5. **明确不做清单**与优化清单同权重（host 袋架构重造、canvas ctx 改名等均明示不做），防止范围膨胀。
6. **行为安全网前置**：先采基线后改码（本次批次 1 踩坑后修正为硬顺序）。

## 4. 方法流程（六步，可复用）

1. **结构测绘**：并行子代理按域提取函数级调用关系/签名/参数形态/模块级状态 + 精读枢纽文件 → 产出分层模型、依赖图、运行链路、横切关注点清单。痛点文件特征：行数排序头部 + import 入度/出度异常 + 文件头注释自述多职责。
2. **问题清单**：逐条编号（P1…Pn），按影响排序，每条带代码证据（文件:行号）。
3. **优化设计**：每项优化（O1…On）对应问题项，标注批次、风险、验证方式；写明"不做"清单。
4. **双角色修订**：异构 peer 独立审改（本次抓出消费方清单失实、行号漂移、阻塞误判 3 类设计失实）+ primary 按当前工作区核实代码漂移 → 终审落定批次定义。设计中的文件清单必须逐文件 grep 核实，不信转述。
5. **实施**：改码前先采探针基线落盘；未提交改动区做行级避让（只动 import/命名行，禁触逻辑区）；build 自检后交付。
6. **验证**（独立实例）：build 独立重跑 → 残留引用扫描（旧符号/旧标识符全仓 grep，含未跟踪新文件）→ 探针基线逐字比对（允许时间戳/行号类漂移）→ 像素断言 → diff 等价审计（机械改动逐行配对）→ API 冻结核对（git diff props/emits/defineExpose）。各方法的适用条件、失效机理与按改动类型的充分组合见 §6。

## 5. 推导链：证据信号 → 问题判定 → 手段选择

套用路径（任意代码库可复述）：测绘产出（§4 步骤 1 的依赖图/调用关系/参数形态/模块状态）→ 逐信号扫描（5.1）→ 问题归类（5.2）→ 手段选择与排序（5.3）→ 阈值与停止判定（5.4）→ 按改动类型选验证组合（§6.3）。规则与语境无关；"本次实例"列引用 table-ex 案例作工作示例。

### 5.1 证据信号识别表（信号 → 可执行识别方法 → 结论）

| # | 信号 | 识别方法（可执行） | 判定结论 | 本次实例 |
|---|---|---|---|---|
| S1 | re-export 转口 | 逐聚合文件的 export 项核对：符号 import 源是另一实现文件、本文件无该符号的定义/包装逻辑（import 源与实现分离，纯转发） | import 图失真：消费方指向聚合壳，实现被二跳遮蔽 | cell-painters 尾部转口 8 符号、editor.js 转口 editor-resolve 全套、interactions.js 转口 schedulers |
| S2 | 运行时注入依赖 | 参数袋（host/ctx/options 大对象）的键被 ≥2 文件回填或调用：grep `袋名.键名`，读/写两侧分处不同文件且两文件间无 import 边 | import 图失真：真实调用边只在运行时出现 | 10 个 composable 经 ~40 键 host 袋互相调用（hitAt/clearCellSelection/applyTreeToggle…） |
| S3 | 隐式共享可变状态 | 单对象字段数大（>20 量级）且写入点分布多文件；或依赖"使用前手动 sync"协议 | 状态读写面不可从签名推断 | paintState（31 字段）被 6+ 模块共享引用，靠每次绘制前手动 sync |
| S4 | 同源重复 | 双证据任一成立：① 注释自认"逐字同源/copy of/保持一致"；② ≥2 文件同函数体（空白归一后逐 token 相等）。仅"看起来像"不判同源 | 漂移风险：一处修复另一处漏 | isSamePoint/recordNumberOf/背景带（注释自认逐字同源） |
| S5 | 跨层反向依赖 | 按分层模型查下层→上层 import 边；或单条 import 边拖入重载荷传递闭包（如整条 UI 组件链） | 层边界失真：影响面横跳，低层受高层牵制 | paint 层 import 编辑层几何函数（连带拖入 form 组件链） |
| S6 | 命名无区分度 | 高频短标识符全库 grep 命中数超大，且跨模块同形异义（同名指不同对象） | 符号检索被噪音淹没 | ctx 在 host/span/deps 三处异义 |
| S7 | 目录/文件多职责 | 单文件/目录承载互不相关多个域：文件头自述多职责、行数排序头部、同文件导出互不消费的符号组 | 按名定位功能的路径断裂 | interactions.js（转口 + 多域职责；批次 3 语义拆分遗留） |
| S8 | 参数形态超标 | 函数位置参数 >5；或打包对象 >10 字段（阈值依据见 5.4） | 调用点需对照签名逐个释义，参数错位不可目检 | withAnchorPreserved 参数化（2B 遗留） |

### 5.3 手段选择决策表（问题类 + 信号 → 手段）

| 问题类 | 信号 | 手段 | 机理（为何有效） | 强度/成本 | 前置条件 | 本次实例 |
|---|---|---|---|---|---|---|
| A | S1 | O1 删 re-export，消费方直引 | import 图 = 依赖图；聚合层只留真正门控逻辑 | 高（根治失真源）/ 低-中（改全部消费方 import 行） | 已按 S1 核实属纯转发 | 三处转口全清，消费方直引（批次 1） |

| A | S5 | O4 跨层共享纯函数独立成模块 | 共享原语（被 ≥2 层消费）单独成文件，重依赖（UI 组件链）不随行 | 高（切断反向边）/ 中（新模块 + 两侧改引） | 函数为纯函数，无层内状态耦合 | editor-geometry 拆分（批次 2A） |

| B | S7 | 目录语义拆分 | 按域拆文件，文件名即检索词 | 高 / 高（动结构，需设计） | A 类已修（依赖图可信），否则拆分边界判定本身失真 | interactions 语义拆分（批次 3 遗留） |
| C | S4 | O5 逐字重复代码单一事实源 | 一处定义多处引用，同源约束由结构天然满足 | 高（根治漂移）/ 中（需等价性校验） | 提取须引用既有约束作为等价性校验点（§6.3 E 类） | isSamePoint/recordNumberOf/背景带 → cell-identity 等（批次 2A） |
| D | S8 | 参数收敛：位置参数 >5 转打包；打包 >10 字段按语义域分组 | 调用点自解释，参数错位在 review 可见 | 中 / 视调用点数 | 接触时渐进执行，不一次性大改、不开专项批次（除非已引发实际缺陷） | 批次 3 遗留 |

次序规则（先机制后搬移）：

1. 机制类（O1/O2/O3）先于搬移类（O4/O5/目录拆分）：前者只动 import/注释/命名行，diff 可逐行配对，走 §6 M 类低成本验证通道；后者动文件边界，必须先采探针基线（§6 S/E 类）。混批则整批按所含最高要求类型验证。
2. 依赖序：S7 的拆分手段依赖 A 类先修——依赖图失真状态下判定的拆分边界不可信；A 类修完即用 §1 判据复测（静态手段能否回答功能定位/影响面），未达标再进 B/C/D。
3. 搬移只用于切断重依赖边（O4）或建立单一事实源（O5），不为美学搬移；参数收敛只在接触调用点时顺带执行。

### 5.4 判定阈值与停止条件

| 阈值 | 默认值 | 依据 | 备注 |
|---|---|---|---|
| 位置参数转打包 | >5 | 5±2 为短期记忆组块上限：调用点超过 5 个字面量序列即无法目检语义，错位不可见 | 校准默认值，有实测证据可调 |
| 打包字段语义分组 | >10 | >10 字段单袋必混装多语义域；消费方只消费子集，子集边界即分组边界 | 同上 |
| 共享原语独立成模块 | 被 ≥2 层消费 | 1 层消费留本层；2 层即产生跨层检索需求与反向边风险 | 结构判定，非数值阈值 |
| 同源重复判定 | 双证据任一（注释自认 / 归一化后同函数体） | 单一"相似"证据误判率高，会合并不该合并的代码 | 证据不足则不提取 |
| 痛点文件入围 | 行数排序头部 + import 入度/出度异常 + 文件头自述多职责 | 体量/耦合/职责三个独立维度的代理指标联合定位 | §4 步骤 1 测绘筛选 |

停止条件：

1. 批次容量：单批文件数/风险级超出执行槽位单会话负荷即拆批（本次 19 文件批次 2 → 2A 机械归一 / 2B 提取+参数化，按风险级隔离）；宁可多批不硬塞。
2. 基线前置：探针基线不可回溯，无基线的改动批次不得启动（§6.4）。
3. 在途改动冲突：目标区存在未提交改动且无法行级避让（只动 import/命名行、禁触逻辑区）时，该区域推迟批次。

"明确不做"划定程序（不做清单与优化清单同权重，逐条标注理由类型）：

| 不做理由类型 | 判定 | 本次实例 |
|---|---|---|
| 收益/成本倒挂 | 失真源已可用低成本手段补齐（如 S2 已有 O2），根治需架构换血，超出"检索效率"目标 | host 袋架构重造不做 |
| 收益为零或负 | 改名/搬移脱离生态惯例，反而降低检索性 | canvas ctx 改名不做（平台 API 语境词） |
| 风险当批不可控 | 改动落在未提交区或需特殊校验，当批无法验证闭环 | 2B 推迟到独立批次（需知识库双约束校验） |

## 6. 验证矩阵（按改动类型）

### 6.1 改动分类（按 diff 形态判别）

| 类型 | 定义 | diff 形态判别 | 验证难度 | 本次实例 |
|---|---|---|---|---|
| M 机械归一 | 改名/直引/搬移，语义逐行等价 | 仅 import 行改写、标识符替换、整块平移，无新逻辑 | 低（等价性可证） | O1 直引、O3 改名（批次 1/2A 主体） |
| S 结构拆分 | 新建模块，代码从源文件迁出 | 新文件 + 源文件删除块 + 两侧引用改写 | 高（等价性不可逐行证明） | O4 editor-geometry、cell-identity 新模块 |
| E 行为等价提取 | 重复实现合一为单一事实源 | ≥2 处删除相似块 + 1 处新增定义 + 调用点改引 | 高（"两处等价"是断言不是事实） | isSamePoint/recordNumberOf/背景带提取 |
| C 签名收敛 | 参数打包/分组，调用点重排 | 函数签名与调用点参数列表同步变化 | 中-高（编译期可静默通过） | withAnchorPreserved 参数化（2B 遗留） |

### 6.2 方法适用性表

| 方法 | 验证什么 | 适用条件 | 失效场景（机理） | 成本 |
|---|---|---|---|---|
| build/编译自检 | 语法与引用完整性 | 任何改动；永远第一步 | 类型系统不覆盖运行时动态键名（S2 参数袋场景下漏转换键名编译不报错）→ 本次 isSameCell 漏转换 build 全过，hover 时 6×ReferenceError、tooltip 全断 | 低 |
| 残留引用扫描 | 旧符号清零 | 改名/直引/搬移/提取后 | `git grep` 不覆盖未跟踪新文件（假阴性）；动态拼接的标识符 grep 不到 → 全仓 grep 含 untracked、按自由标识符匹配 | 低 |
| diff 等价审计 | "仅机械归一"证明 | M 类，diff 可逐行配对 | S/E/C 无法逐行配对；只看形状不核语义会漏配对行内的表达式改动 → 配对须同时核对等价 | 中 |
| 探针基线比对 | 行为冻结等价 | 有可触发组件行为的运行环境 | 覆盖面 = 探针点位覆盖面：未触达的交互路径比对不到（本次 hover 缺陷靠 hover 交互点位才抓到）；基线不可回溯，改码前采集落盘是硬顺序 | 高 |
| 像素断言 | 渲染输出等价 | canvas/视觉输出类组件 | 对非视觉逻辑（纯函数/数据流）无感；计数断言粒度粗，与 console 原文序列互补 | 中 |
| API 冻结核对 | 对外契约零变化 | 库/组件/模块对外导出的重构 | 不检内部行为；范围须含 props/emits/defineExpose/事件时序（git diff 复核） | 低 |

执行次序（低成本排除法）：build → 残留扫描 → diff 等价 / API 冻结 → 探针基线 + 像素断言。前序通过不替代后序，只让后序聚焦。混合批次按所含最高要求类型的组合执行。

### 6.3 充分组合（每类改动的"够用"判据）

| 改动类型 | 充分组合（够用） | 补充手段（按需） | 理由 |
|---|---|---|---|
| M 机械归一 | build + 残留扫描 + diff 等价审计 | 触及运行时动态查找（动态 import/键名拼接）时，探针基线升级为充分项 | 逐行配对证明语义等价，行为正确性由等价性传递，故 diff 等价审计即像素断言/基线的高效替代；动态查找是等价性传递的断点 |
| S 结构拆分 | build + 残留扫描 + 探针基线（console 警告/错误原文序列 + 像素断言计数，逐字比对，允许时间戳/行号类漂移） | 模块对外导出变化时加 API 冻结 | 迁出代码在新位置可能带回不同依赖闭包（O4 切断重边正利用此机理）；diff 无法配对，行为面只能由基线证明 |
| E 行为等价提取 | build + 残留扫描 + 探针基线 + 等价性校验点核对 | — | "两处同源"是断言：须以注释自认的约束/既有调用约束为校验点逐条核对，基线再证消费侧行为不变 |
| C 签名收敛 | build + 全部调用点逐一参数位核对 + 探针基线 | 有类型系统时加类型检查 | 对象键无序，打包/分组错位编译期可静默通过，只能点位核对；基线兜底运行时 |

### 6.4 探针基线的适用边界与豁免程序

- 必须采基线：S/E/C 类；M 类触及动态查找；任何影响面不可静态推断的改动。
- 可豁免（以 diff 等价审计替代）：纯 M 类，且不触及动态查找、不动行为路径。
- 豁免程序合法性：豁免决定须在设计文档写明理由与 diff 配对范围，验证员核对配对完整性后方可免采；无记录的豁免视为未验证。
- 顺序约束（不可违反）：基线是实施者职责（写进任务简报），改码前采集落盘；基线不可回溯，验证员无法事后补采，只能同口径复采逐字比对。
